# Security Policy

StealthSnark is a research implementation of "Single-Server Private Outsourcing
of zk-SNARKs". **It has not been audited and is not suitable for protecting real
assets or real secrets.** Please treat it accordingly.

## Reporting a vulnerability

Report privately by email to <kannar432@gmail.com> with `[stealthsnark]` in the
subject. Please do not open a public issue for a security bug.

Useful things to include: what property you believe is broken (soundness,
witness privacy, availability), the smallest reproduction you have, and which
commit you tested. There is no bounty and no formal SLA — this is a personal
project — but reports will be acknowledged and credited unless you prefer
otherwise.

## What is in scope

The properties the implementation actively tries to hold, and the suites that
check them (see `VERIFICATION.md`):

| Property | Meaning | Guarded by |
|---|---|---|
| Witness privacy | The server learns nothing about the witness from the masked vectors | `tests/privacy.rs` |
| Soundness (malicious mode) | A server returning wrong MSM results is detected | `tests/malicious_soundness.rs` |
| Correctness | Server-aided proofs match stock `ark-groth16` | `tests/differential.rs` |
| Availability | Untrusted input cannot panic, OOM, or wedge the server | `tests/service_hardening.rs`, `cargo fuzz` |
| Session isolation | One client cannot read, replace, or corrupt another's session | `tests/service_hardening.rs`, `tests/session_stress.rs` |

## What is explicitly out of scope

These are known, deliberate limitations rather than bugs. Reports about them are
welcome as discussion, but they are not vulnerabilities in the current design.

- **No transport security.** The server speaks plain HTTP and does not
  authenticate clients beyond the per-session bearer token it issues. Terminate
  TLS at a reverse proxy and put an authenticating layer in front of it. LPN
  masking protects witness *confidentiality* on the wire, but nothing in this
  repo protects *integrity* of the transport.
- **No client authentication or quota.** Anyone who can reach `/v1/setup` can
  consume a session slot. `STEALTHSNARK_MAX_SESSIONS` bounds the damage; it does
  not attribute it.
- **Semi-honest mode trusts the server's arithmetic.** Only the malicious-secure
  path (`malicious_*`) detects a cheating server. Using semi-honest mode against
  an untrusted server is a misuse, not a vulnerability.
- **Trusted setup.** The Groth16 proving key is generated by the client in the
  demo binaries. Ceremony security is out of scope.
- **Timing side channels in session lookup.** Token lookup is a `HashMap` probe
  and is not constant-time. Tokens carry 256 bits of entropy, so there is nothing
  for an attacker to walk toward; this becomes in scope if tokens ever get
  shorter or derived from client input.
- **Denial of service by resource exhaustion within configured limits.** The
  server admits `max_concurrent_msm` MSMs of up to `max_body_bytes` each; those
  knobs are the contract. Reports that the defaults are unwise are welcome.

## Hardening the deployment

Defaults are chosen to fail safe rather than to be convenient:

- Binds `127.0.0.1` by default, not `0.0.0.0`. Exposing it is a deliberate act.
- Session generators are evicted after an idle TTL and capped in count.
- Request bodies are capped; the cap times the MSM concurrency is the worst-case
  memory from in-flight bodies, and the server logs that product at startup.

See the configuration table in `README.md` for the knobs.
